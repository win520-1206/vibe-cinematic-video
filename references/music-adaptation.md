# 音乐先行的适配规则

## 默认素材与优先级

用户本次提供或指定的曲目优先；没有换曲则使用assets/defaults.json登记的默认音乐。本Skill默认音乐来自用户此前概率主题参考视频的完整音轨，资产为assets/music/default-reference.m4a，无重编码提取。它不是经过音源分离的纯音乐stem。

默认风格是cinematic-spatial；音乐与风格分别选择。用户可以保留风格换音乐，或保留音乐换风格，不把两者绑死。

若默认资源缺失，核查清单和用户指明的原路径；仍不可用才询问路径或替代素材，不静默挑另一首曲。不得仅根据原工程的120秒文件假定音乐只有120秒。

## 先分析，再写具体落点

1. 读取实际时长、声道、采样率，确认是音乐、完整参考混音还是含人声材料。
2. 转为分析用PCM WAV，保留原曲用于最终混音；在新项目缓存分析文件，不改写Skill内默认素材。
3. 按本次fps提取低/中/高频、RMS、候选瞬态。
4. 分析节奏周期/BPM候选、节拍网格和强瞬态；识别蓄势、段落变化、较安静区与持续高能量的高潮候选。
5. 实际听取并复核鼓点、强拍和高潮。算法无法确认某一瞬态是不是鼓，也不能保证最响段落就是叙事高潮；听取不可用时明确标记，给出候选，不能声称已听懂。
6. 建立music-analysis.json与beat-map.json，再决定开场、标题退场、关键揭示、转场和片尾。

工具链：明确指定可用ffmpeg，将选定素材解码为PCM WAV；运行audio_features.py，再运行music_structure.py。两者的结果是剪辑参考，而不是可以跳过听取和导演判断的最终节拍表。

```text
python scripts/audio_features.py --input analysis.wav --fps USER_FPS --output audio-features.json
python scripts/music_structure.py --features audio-features.json --output music-analysis.json
```

## 把音乐映射为画面

|音乐信息|优先安排的画面|
|---|---|
|弱拍或低能量开场|留悬念、微弱信号、少量字幕|
|稳定鼓点|局部粒子响应、运动阶段、节奏性积累|
|渐强或蓄势|相机准备、尺度扩展、对象聚合|
|确认的高潮或强拍|关键结构揭示、问题答案、明确转场|
|安静或稀疏段落|公式、数据、因果解释与阅读|
|收束与尾音|结论、余韵、下一集问题与片尾|

主揭示可选主高潮，次级镜头可选邻近强拍。不要每个鼓点都切镜头，不让所有粒子同时闪。复杂台词与数学阅读时，优先保留阅读窗口，再调整镜头落点。

音效绑定科学事件；音乐卡点不能把“先相互作用、后发光”倒置。不能为迁就曲目随意加速概率过程或伪造数据积累。

## 时长不匹配

视频短于曲目：根据段落选择合适截取点与结尾，记录原曲时间和本片时间的映射。截取后重新计算局部节拍与高潮对应时刻。

视频长于曲目：向用户说明可选整段循环/音乐段落重组/追加音乐/调整片长，取得本次选择；不能偷偷无限循环或擅自变速。多集可以用同曲不同段落或同曲重复，各集方案在调用约定中确认。

用户指定关键时刻时，以明确要求为约束；若与音乐冲突，展示具体候选调整。17秒只是历史案例的要求，新作没有预设标题长度或高潮时刻。

## 缓存与验收

缓存应关联所选曲目的路径或哈希、截取起终点、播放速度和分析fps。任一改变后重新生成特征及beat-map，不能套用默认曲旧数据。

事件表记录musicSourceSeconds、timelineSeconds、frame及事件用途。导出后实际检查落点前后帧、音轨是否偏移、声音是否完整；页面进度和源码时刻不能代替成片证据。
