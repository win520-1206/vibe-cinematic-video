# 项目约定与调用

## 新会话提示词

```text
使用 $vibe-cinematic-video 制作科学可视化短剧。
主题：光合作用与能量转换。
受众：大学生；2集，每集90秒；16:9，1080p30。
沿用默认连续空间动画风格的空间动画与声画互动方向，默认字幕对话，不配机械人声。
音乐和参考资料见本工作目录。
为本作建立独立目录，先核验资料，拆解参考，制作包含科学过程的代表性样片，再按我的后续确认完成全片。
```

若用户已明确直接完成全片，继承授权，不再次强制样片确认。用户只要重剪某几秒时，不扩大为整片风格重做。

## 调用问答协议

每个新作品先询问未给出的：主题/受众/用途、几集、每集或总时长、画幅/平台/输出规格、先样片还是直接整片、材料和输出目录。已在本次请求给出的值不重复问。音乐默认使用此前提供的曲目，风格默认cinematic-spatial；告诉用户可以换，不强制为这两个默认项停下来等确认。

不要自动填三集、120秒、17秒。用户未决定时可以先讨论或给方案，未获本次参数前不启动依赖时长的全片渲染。

## 项目约定内容

assets/project-contract.example.json提供待收集参数的空配置：集数、时长、fps、宽高和输出目录均为null，keyEvents为空。确认问答并分析音乐后才填入。字段分成：project/输出规格/story/音乐与风格/关键事件/工作阶段。脚本inspect_media只使用其中视频规格与音频要求，不验证剧情、科学来源或主观质量。

卡点是全片秒数，kind区分title_cut、interaction、reveal等。音频特征的fps应与视频一致。场景边界、字幕时刻、音效和Composition帧数必须来自同一份约定或可追溯的变换。

不得把null变成历史案例值来绕过问答。inspect_media.py只用于参数已经确定的成片；未收集完的空配置应先完成问答。不要把案例人物、素材名称、三集、120秒或17秒自动注入新作。

## 可维护的项目文档

按规模选择文件，不强制空目录：

- BRIEF.md：目标、范围、已确认风格、输出与边界。
- events.json：各段时刻、状态变化、声音和知识含义。
- sources.md：说法、原始来源、日期、假设、画面引用方式。
- assets.json：本地/生成/用户素材的路径、用途与真实来源。
- PROGRESS.md：已完成、用户确认、正在进行、阻碍和下一步。
- qa.json：实际文件规格、关键帧证据、解码与音轨结果。

## 事件表示例

```json
{
  "id": "interaction-01",
  "at": 22.4,
  "object": "sample",
  "before": "incoming particle, no scintillation",
  "action": "interaction followed by outward light propagation",
  "after": "sensor response available for reconstruction",
  "sound": {"effect": "subtle-chime", "offset": 0},
  "caption": "相互作用留下微弱闪烁",
  "science": "速度放慢；数量与尺度示意"
}
```

这只是关联方式示例。新科学过程应重新写before/action/after，不能沿用其他题材的因果链。

## 输出与复现

成片按版本分目录，保存实际文件名清单。输出总览应说明片长、画幅、音频方案、模拟边界、有效渲染入口和验收位置。localhost播放器可重新启动；MP4和源工程才是持久交付物。

复现前核对资产清单、依赖版本、系统字体、Python库、浏览器与编码器路径，不把“之前成功”当作当前机器可运行的证明。
